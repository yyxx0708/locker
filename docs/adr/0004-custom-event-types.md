# ADR 0004：自定义事件类型

- 状态：已采纳
- 日期：2026-11-12

## 背景

1.2 及更早版本把事件类型硬编码为「锁射 / 开锁射精」，统计图、月历圆点和事件列表都只有蓝 / 橙两种。实际使用中需要自定义事件名称和统计颜色。

## 决策

1. 新增 `event_types` 表，字段为 `typeKey`、`name`、`colorArgb`、`sortOrder`、`builtIn`；`typeKey` 唯一。
2. `events.type` 继续保存类型标识（内置为 `locked` / `unlocked`，自定义为 `custom_<uuid>`），通过 `event_types` 解析名称与颜色。
3. 初始化时写入两项内置类型。内置类型可改名、改色，但**不能删除**；自定义类型可以新增、改名、改色和删除。
4. 删除自定义类型时，在同一事务里删除该类型名下的全部事件（所有人物），并在界面上二次确认。
5. 自定义颜色从预设色板中选择，色板取中等明度，兼顾白天与黑暗主题。
6. 统计改为按事件类型动态计算：`StatsResult.eventStats` 包含每种类型的次数与分桶；汇总、年柱状图、月历圆点、图例、事件列表均按类型定义渲染。
7. 备份升级到 schemaVersion 3，新增 `eventTypes` 数组。导入 1.1 / 1.2 备份时使用两项内置类型；导入 1.3 备份时校验内置类型存在、类型标识唯一、事件引用有效。
8. 数据库升级使用 Room `Migration(2, 3)` 创建表并写入内置类型；1.1 数据库按 1→2→3 链式迁移。

## 后果

- 事件类型是全局配置，不属于某个人物；所有人物共享同一套类型与颜色。
- 改名 / 改色会立即反映到历史记录与统计中，不需要迁移事件数据。
- 删除自定义类型会永久删除该类型的事件；界面需明确提示。
- 极端自定义颜色在深色主题下可能对比度不足；预设色板用于降低该风险。
