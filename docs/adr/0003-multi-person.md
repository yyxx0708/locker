# ADR 0003：多人物独立计时

- 状态：已采纳
- 日期：2026-11-12

## 背景

1.1 及更早版本只有一个全局佩戴状态：所有分段和事件都属于同一个人。实际使用中需要同时跟踪多个人，每个人有独立的戴上 / 取下时间、事件和统计，并且可能同时处于佩戴中。

## 决策

1. 新增 `persons` 表；`wear_segments` 和 `events` 增加 `personId` 外键字段（逻辑外键，删除由仓库层显式级联）。
2. 「同一时刻只能有一个佩戴中的分段」的约束改为**按人物独立**。不同人物可以同时佩戴，计时互不影响。
3. 统计页始终只展示**当前人物**的数据；当前人物在主页面、统计页和设置页之间共享，并持久化到本机偏好。
4. 删除人物时，在同一个事务里删除该人物的全部分段和事件；至少保留一个人物。
5. 备份升级到 schemaVersion 2，包含 `persons` 以及带 `personId` 的分段 / 事件。导入 1.1 的 schemaVersion 1 备份时，自动创建默认人物「我」并把全部旧记录归入该人物。
6. 数据库升级使用 Room `Migration(1, 2)`：创建 `persons`、插入默认人物、重建两张记录表并写入 `personId = 1`，不丢失旧数据。

## 后果

- 旧数据升级后归入「我」，可在设置中改名。
- 1.1 无法导入 1.2 导出的 schemaVersion 2 备份（会提示不支持的版本）；升级后请使用 1.2 恢复。
- 人物列表、切换条、人物管理界面成为新的 UI 组成部分。
- 统计计算本身不变，仍按传入的当前人物分段 / 事件计算，避免在纯函数里引入人物过滤逻辑。
