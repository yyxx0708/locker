# ADR 0007：桌面小组件只读，且每个实例独立绑定一个人物

状态：已采纳（2026-11-14）

## 背景

小组件最初按「跟随 App 当前人物」实现，并带有锁上/开锁按钮与今日随机数。实际使用后暴露三个问题：

1. 多人物场景下，桌面上无法同时看到两个人物的状态，每次都要回 App 切换。
2. 小组件上的按钮绕过了 App 内的二次确认；而确认框在 `RemoteViews` 中无法实现（必须开 Activity 或发通知），与「不打开 App 就能操作」的目标冲突。
3. 随机数与佩戴状态同屏，但随机数每天只需用一次，占用主要版面。

## 决定

1. **只读**：小组件不提供任何写操作，整卡点击只打开 App。
2. **每实例独立绑定一个人物**，同一人物只能被一个实例绑定；添加时通过配置界面选择，API 28+ 支持长按重新配置。
3. **绑定与应用内「当前人物」互不影响**，但点小组件会把 App 的当前人物切到该实例绑定的人物。
4. **不显示随机数**；显示本次佩戴时长与今日照片打卡状态。
5. 导入 JSON 备份后，按绑定时的名称**精确匹配**生成恢复候选，**不静默改绑**，由用户集中确认一次。

## 理由

- 只读消除了「小组件操作绕过确认」的一致性缺口，也让实现不必在广播接收器里处理事务与失败回滚。
- 每实例绑定是唯一能同时观察多个人物的方式，且不与「当前人物」争夺同一份状态。
- 打卡状态选「今日是否上传每日照片」而非「是否生成随机数」：随机数每天自动生成，显示出来几乎没有信息量。
- 导入后按名称恢复：人物名称在应用内本就唯一，精确匹配足够可靠；但 ID 会重建，静默改绑可能把小组件指到用户没预期的对象，因此坚持确认。

## 后果

- 需要一个配置 Activity，并为每个实例维护绑定（`SharedPreferences`，键为 `appWidgetId`）。
- 删除人物时必须清理绑定，否则会出现指向不存在人物的实例。
- 名称被修改后，绑定里保存的名称要在刷新时同步更新，否则导入恢复会匹配失败。
- 小组件不再能替代 App 完成锁上/开锁，桌面操作的入口只剩「打开 App」。
